AI에게 작은 프로그램을 맡겨도 내 컴퓨터 전체를 열어줄 필요는 없어요. GitHub Copilot의 새 실행 권한 제한과 로컬 모델 선택을 이해하면, 작업에 필요한 범위를 정하고 결과를 직접 검토하기가 쉬워집니다.

이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.

1. 먼저 ‘어디까지 만질 수 있는지’ 정해요 🛡️

{{section1}}

코딩 에이전트는 설명을 넘어 파일을 고치고 명령도 실행하는 AI예요. 그래서 답변이 그럴듯한지와 함께, 내 PC에서 무엇을 할 수 있는지도 중요해졌습니다.

샌드박스는 작업용 울타리라고 생각하면 쉬워요. AI가 실행하는 명령에 허용할 파일·네트워크·인증정보의 범위를 설정하는 기능입니다. 이번에 Copilot CLI, Copilot 앱, VS Code의 Agent Host를 사용하는 세션에 로컬 샌드박스가 정식 제공됐어요. 로컬 샌드박스에는 추가 이용료가 없지만 Copilot 자체가 모두 무료라는 뜻은 아닙니다.

로컬 샌드박스는 기본적으로 꺼져 있어요. CLI와 앱의 설정도 별개입니다. CLI에서 켰다고 앱 작업까지 같은 제한을 받는다고 생각하면 안 돼요.

CLI는 텍스트 명령으로 도구를 쓰는 방식입니다. CLI 세션에서 `/sandbox enable`로 켜고 `/sandbox status`로 현재 적용 상태를 볼 수 있어요. `/sandbox policy`는 실제로 허용된 경로와 네트워크 조건을 보여줍니다. 앱은 프로젝트 설정과 현재 세션의 설정을 살펴보는 방식이에요.

울타리를 켜도 인터넷이 전부 끊기는 것은 아닙니다. CLI의 기본 설정은 외부 인터넷 접근을 허용하고 로컬 네트워크 접근은 꺼 둡니다. 필요한 경로와 연결 대상은 작업에 맞춰 정해야 해요. 운영체제에 따라 지원 조건과 제한 방식도 다릅니다.

가상 컴퓨터 안에서 모든 작업을 완전히 격리하는 구조도 아니에요. CLI 내부 파일 도구는 설정을 따르도록 자체적으로 확인하며, 원격 MCP 서버는 이 로컬 샌드박스 밖에 있습니다. MCP는 AI가 외부 도구와 연결하는 통로예요. 중요한 자료라면 조직의 보안 기준에 맞는지 별도로 판단해야 합니다.

2. 로컬 AI가 보여도 자동으로 안전해지는 건 아니에요 💻

{{section2}}

로컬 모델은 내 컴퓨터에서 실행하는 AI 모델입니다. GitHub Copilot CLI 1.0.94-0부터 `/model`에서 실행 중인 Ollama의 지원 모델을 찾아볼 수 있어요. Ollama는 로컬 모델을 실행하는 도구입니다.

Ollama와 모델을 먼저 설치해야 하고, 모델은 도구 호출과 스트리밍을 지원해야 합니다. 도구 호출은 AI가 필요한 도구를 요청하는 기능, 스트리밍은 답을 조금씩 보내는 방식이에요. 목록에서 발견했다고 자동으로 추가되지는 않으며 제공자와 연결 주소를 검토한 뒤 선택합니다.

로컬 모델 선택과 오프라인 모드는 별개의 설정이에요. 로컬 모델을 골라도 GitHub 사용 정보 전송이 자동으로 꺼지는 것은 아닙니다. 원격 제공자를 연결했다면 입력과 코드 맥락이 네트워크로 전달될 수 있어요.

예를 들어 개인용 독서 기록 프로그램에 제목 검색을 추가한다고 가정해 볼게요. 원래 화면은 기록 목록만 있고 검색칸이 없습니다. 실제로 실행해 본 결과를 소개하는 예시는 아니에요.

요청은 이렇게 구체화할 수 있습니다. “제목 검색만 추가해 주세요. 원래 기록 파일은 바꾸지 말고, 수정한 파일 목록과 확인 방법을 알려 주세요.” 작업 전에 별도 복사본을 준비하고, 허용 경로에 원본이 포함되는지도 살펴봅니다.

예시 결과는 검색칸을 넣은 수정안과 변경 파일 목록이에요. 내가 확인할 차이는 ‘검색한 제목만 남는지’, ‘검색을 지우면 원래 목록이 돌아오는지’, ‘원본 기록이 그대로인지’입니다. 요청 문장만으로 파일 보존이 보장되는 것은 아니므로 접근 설정과 실제 결과를 함께 봐야 해요.

처음부터 로컬 모델을 반드시 쓸 필요도 없습니다. 이미 준비된 환경이 있고 도구 호출을 지원하는 모델을 비교하려는 사람에게 이번 탐색 기능이 유용해요. 설치·메모리·작업 적합성을 판단하기 어렵다면 익숙한 환경에서 작은 작업부터 시작할 수 있습니다.

3. 이용 계정·저장소 계정·결과 검토를 나눠 봐요 👀

{{section3}}

저장소는 코드와 변경 기록을 모아 두는 공간입니다. Copilot 앱에서는 Copilot 이용 자격을 가진 GitHub 계정과 저장소에 접근하는 계정을 다르게 선택할 수 있어요.

앱 출시 기록은 Settings → Accounts의 Separate Copilot account를 안내합니다. 여러 계정을 가진 사람은 작업에 사용할 저장소 계정과 AI 이용 계정이 각각 무엇인지 구분할 수 있어요. 다만 이 기능이 회사 정책을 우회하거나 접근할 수 없던 저장소 권한을 주는 것은 아닙니다.

계정 분리, 실행 권한 제한, 모델 선택은 서로 다른 판단이에요. 누구의 자격으로 쓰는지, AI 명령이 어디에 접근하는지, 어떤 모델이 요청을 처리하는지를 각각 살펴야 합니다. 이 셋을 따로 보면 문제가 생겼을 때 확인할 대상도 분명해져요.

결과 검토도 편해집니다. VS Code 1.141의 Agents 창에서는 세션을 격자로 나란히 배치할 수 있어요. 서로 다른 수정안을 비교하거나 여러 작업을 따라볼 때 도움이 됩니다. 창이 정리됐다는 이유만으로 코드가 맞다고 결론 내리지는 말아야 해요.

이번 변화는 에이전트에게 파일 작업을 맡기는 사람, 로컬 모델을 이미 준비한 사람, 계정을 나눠 쓰는 사람에게 살펴볼 가치가 있습니다. 조직의 민감한 코드나 높은 수준의 격리가 필요한 작업은 회사 정책과 실행 환경을 먼저 정해야 해요. 선택지가 늘어난 만큼 ‘내가 허용할 범위’도 직접 정하는 것이 핵심입니다.

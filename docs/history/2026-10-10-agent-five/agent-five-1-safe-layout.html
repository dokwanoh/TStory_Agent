구글 AI 코딩 도구를 새로 고르거나 이미 구독 중이라면, 이번 변화에서 먼저 볼 것은 내 구독의 이름과 갱신일이에요. Gemini Code Assist의 Standard·Enterprise 신규 판매는 끝났지만, 기존 구독이 바로 멈추는 것은 아닙니다.

이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.

1. 판매 종료와 사용 종료, 날짜가 달라요 📅

{{section1}}

구글의 10월 9일 공지는 Gemini Code Assist Standard와 Enterprise의 새 구독을 더는 구매할 수 없다는 내용이에요. 코드를 쓰고 고치는 일을 돕는 구글 AI 도구의 판매 경로가 바뀐 것이죠.

기존 이용자는 내 계약 종료일까지 사용과 지원을 받을 수 있습니다. ‘새로 가입할 수 없다’와 ‘오늘부터 못 쓴다’를 나누어 읽어야 하는 이유예요.

자동 갱신은 별도 신청 없이 다음 구독 기간을 이어가는 방식입니다. 구글의 상세 안내에서 연간 구독은 2027년 1월 31일까지 자동 갱신할 수 있고, 월간 구독은 2027년 12월 31일까지 자동 갱신할 수 있다고 설명해요.

팀에서 사용 인원을 늘리는 라이선스 추가는 2027년 1월 31일까지 가능합니다. 기존 구독이 살아 있다고 해서 새 사람을 언제든 추가할 수 있는 것은 아니에요.

예를 들어 회사에서 쓰는 AI 도구 이름에 ‘Enterprise’가 붙어 있다면, 그것만 보고 전환 대상 구독과 같은 상품이라고 생각하면 안 됩니다. Gemini Code Assist Enterprise와 구글이 전환 대상으로 안내하는 Gemini Enterprise는 이름을 구분해 읽어야 해요.

신규 판매 종료일, 갱신 가능 기한, 내가 계약한 마지막 사용일을 세 칸으로 나누어 적어보세요. 앞의 두 칸은 공식 공지에서, 마지막 칸은 내 계약에서 확인할 정보라 서로 대신할 수 없습니다.

2. 왜 Antigravity로 이어질까요? 🧩

{{section2}}

이번 공지에서 구글이 대안으로 안내하는 도구는 Antigravity예요. 안티그래비티는 AI 에이전트가 소프트웨어 개발 작업을 진행하도록 구성한 플랫폼입니다. 에이전트란 답을 말하는 것에서 더 나아가, 허용된 도구로 작업을 수행하는 AI를 뜻해요.

Antigravity 2.0은 여러 로컬 에이전트를 함께 관리하는 작업 공간을 제공합니다. 로컬은 내 컴퓨터 쪽에서 진행되는 작업을 뜻하고, 프로젝트는 관련 대화를 묶어 관리하는 단위예요.

터미널에서 명령을 입력하며 쓰는 CLI, 개발 화면을 중심으로 쓰는 IDE, 사용자 정의 에이전트를 만드는 SDK도 안내되어 있어요. 처음 보는 독자는 약어를 전부 외우기보다 ‘어느 화면에서 어떤 일을 맡길 것인가’로 구분하면 편합니다.

이번 10월 9일 뉴스의 핵심은 구독 전환이며, 이 기능들이 이날 모두 처음 출시됐다는 뜻은 아닙니다. 구글은 이미 8월 20일에 자격을 갖춘 Gemini Enterprise 구독에 Antigravity를 포함하는 방향을 발표했어요.

따라서 큰 흐름은 코딩 보조 상품 하나의 새 판매를 끝내고, 여러 작업을 맡기는 에이전트 플랫폼으로 이용 경로를 연결한다는 것입니다. 이 방향이 내 작업에도 더 편할지는 별도로 판단해야 해요.

회사 계정으로 옮기려면 이용 자격과 관리자 설정이 중요해요. 개인이 작은 프로그램을 만들어보는 경우와 조직의 코드·권한을 관리하는 경우는 선택 기준이 같지 않습니다. 이번 기업용 구독 공지를 개인용 AI 서비스 전체의 종료 소식으로 확대해서 읽지 마세요.

3. 처음 시작한다면 작은 결과물로 비교해요 ✅

{{section3}}

구독 변경 소식이 나왔다고 오늘 모든 파일과 작업을 옮길 필요는 없어요. 먼저 현재 이용 중인 구독이 무엇인지 확인하고, 새 도구에서 실제로 필요한 일을 작은 범위로 정해보는 편이 좋습니다.

가령 공부할 때 쓰는 타이머를 만들어보고 싶다고 해볼게요. 아래는 직접 실행한 결과가 아닌 가상의 요청과 확인 예시입니다.

막연한 요청은 ‘공부 타이머 만들어줘’예요. 이를 ‘25분 타이머에 시작·일시정지·초기화 버튼을 넣고, 인터넷 연결이나 회원가입 없이 내 컴퓨터에서 쓰게 해줘’로 구체화할 수 있습니다.

예시 결과가 타이머 화면이라면, 멋진 모양만 보고 완료로 판단하지 않아요. 일시정지했을 때 시간이 멈추는지, 다시 시작하면 남은 시간부터 이어지는지, 초기화하면 25분으로 돌아오는지를 살펴봅니다.

요청하지 않은 회원가입이나 외부 서버 연결이 생겼다면 그 차이를 다시 설명해 수정해달라고 할 수 있어요. 이 과정은 특정 도구가 반드시 성공한다는 증명이 아니라, 두 도구에 같은 조건을 주고 결과를 비교하는 방법입니다.

비교할 것은 AI의 말솜씨보다 내가 원하는 결과를 확인하고 고칠 수 있는가예요. 작은 도구 하나의 실행 방법과 수정 내역을 이해할 수 있다면, 다음 프로젝트를 맡길 범위를 정하기도 쉬워집니다.

{{workflow}}

새 구독을 고르는 사람은 새 판매가 종료된 등급을 기준으로 계획하기보다 현재 제공되는 경로를 살펴볼 만해요. 기존 이용자는 계약과 갱신 일정 안에서 전환 계획을 세우고 작은 작업부터 비교해보면 됩니다.

반대로 업무에 꼭 필요한 기능·조직 권한·이용 조건이 확인되지 않았다면, 외형이 비슷하다는 이유만으로 전부 옮기는 접근은 적절하지 않아요. 이번 뉴스에서 얻을 실용적인 결론은 ‘즉시 갈아타기’보다 ‘내 계약을 알고, 내 작업으로 선택하기’입니다.

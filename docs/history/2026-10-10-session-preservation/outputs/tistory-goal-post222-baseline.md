# 사용자 확정 목표 — post 222 기준의 새 글 1개

지금부터 아래 기준으로 새 글 1개를 빠르게 작성하고 게시한다. 진행 과정과 실제 결과를 기록하여 다음 시도에서 검증된 성공 경로를 재사용한다.

## 1. 목표와 주제 선정

AI tech 관련 주제 중 초보 독자도 관심을 가질 만하고, 일상에서 활용하거나 선택에 도움을 받을 수 있는 대중적인 주제를 선정한다. 현재 관심과 향후 관심 가능성은 확인 가능한 근거로 판단하고, 전망은 사실과 구분한다.

TISTORY GROWTH OS의 허용 범위인 금융/보험, 법률, 부동산, IT/소프트웨어 안에서 선정한다.

신선도는 조사 시점 기준 36시간 이내의 공식 발표·업데이트를 우선한다. 발표 시각과 실제 변경 내용을 확인하고, 기존 게시글과 내용이 크게 겹치지 않게 한다. 정확한 발표 시각을 확인할 수 없으면 확인 가능한 날짜와 한계를 기록한다.

주제 확정 전에 ‘독자가 해결할 질문’, ‘글의 한 문장 결론’, ‘관련 상품이 필요한 구체적인 이유’를 정한다. 주제·근거·상품 관련성을 확인한 뒤 본문과 이미지 생성을 시작한다.

## 2. 본문 작성

$korean-insight-writing과 $eli5를 적용해 초보 독자가 편하게 읽는 한국어 해설글을 약 3,000자 수준으로 작성한다. 분량을 맞추려고 같은 설명을 반복하지 않는다.

게시글 맨 앞에는 실제 본문의 도입문 1~2문장을 배치한다. 독자가 얻을 도움과 핵심 결론을 바로 제시하여, 목록 요약에서도 글의 내용이 드러나게 한다. 광고 문구나 목록 노출만을 위한 별도 문장을 넣지 않는다.

한 문단에는 한 가지 생각을 담고, 보통 1~3문장으로 쓴다. 전문용어는 처음 나올 때 쉬운 말로 설명한다.

중요한 조건·수치·단위·비교 기준·출처와 한계를 보존한다. 검증된 자료에 없는 사실, 성능, 기능, 직접 사용 경험을 추가하지 않는다. 쉽게 다듬는 과정에서도 의미를 바꾸지 않는다.

독자가 따라 이해할 수 있는 구체적인 예시를 최소 1개 넣는다. 원문·요청·예시 결과·확인할 차이를 연결한다. 직접 실행하지 않은 예시는 가정임을 짧게 표시하고 실제 사용 결과처럼 쓰지 않는다.

요금이나 수치가 나오면 먼저 용어와 단위를 설명한다. 비교가 복잡하면 짧은 표로 정리한다. 같은 주의사항이나 ‘확인하세요’라는 결론을 여러 절에서 반복하지 않는다.

마지막에는 ‘어떤 경우에 써볼 만한지’, ‘어떤 경우에는 다른 접근이 필요한지’를 독자가 판단할 수 있게 정리한다.

## 3. 스타일과 연결 버튼

post 222의 확인된 스타일·배치·광고 구성을 따르고, 검증된 성공 경로와 설명·이미지 연결 방식을 참고한다. 충돌하는 부분은 이번 명시 지침을 우선한다.

30초 요약, 친근한 말투, 적절한 이모지, 문단 간격을 활용한다. 각 주요 절의 제목만 크게 하고 볼드로 강조한다. 본문 문장에는 제목 크기나 볼드가 이어지지 않게 하되, 주요 절마다 제일 강조가 필요한 단 하나의 문장이나 키워드는 볼드 처리한다.

독자가 공식 조건을 확인하거나 다음 행동을 하려는 위치에 버튼을 배치한다. 버튼 이름에는 클릭하면 확인할 내용을 적는다. 핵심 설명을 숨겨 클릭을 유도하지 않는다.

공식 자료와 직접 관련 있는 글을 연결하고, 내 기존 게시글도 연관성이 있을 때 활용한다.

## 4. 쿠팡 상품 선정

$coupang-partners-api로 상품을 검색하고 실제 상품 종류·옵션·제휴 링크를 확인한다. API 키는 키체인에서 내부적으로만 사용하며 출력하거나 복사하지 않는다.

상품은 본문에서 다루는 구체적인 활용이나 독자의 필요에 연결되어야 한다. ‘컴퓨터로 쓰는 서비스이므로 키보드’, ‘AI 글이므로 아무 AI 관련 상품’ 같은 포괄적인 이유로 선정하지 않는다.

상품마다 ‘이 글을 읽는 사람이 어떤 상황에서 왜 필요로 하는가’를 판단한다. API 검색 성공과 옵션 일치만으로 관련성까지 통과했다고 판단하지 않는다. 추가 구매가 필요한 것처럼 근거 없이 설명하지 않는다.

관련 없는 상품을 끼워 넣거나 상품에 맞추려고 본문의 사실을 바꾸지 않는다.

선정 이유를 독자에게 설명할 짧은 문장도 상품 검토 단계에서 확정한다. 실제 확인한 상품 내용과 본문의 활용 상황을 연결하고, 이 문장을 게시 후 작성자 댓글에 사용한다.

## 5. 본문 정지 이미지와 표지

각 주요 절, 즉 소제목 단위로 내용을 가장 잘 설명하는 정지 이미지 1장을 제작한다. 실사를 우선하되 설명이 어려우면 도해나 다른 표현 방식을 선택한다.

생성 전에 이미지마다 ‘이 그림이 설명할 본문의 한 가지 내용’을 정한다. 결과 이미지에서도 그 내용이 바로 드러나야 한다.

이전 생성 이미지와 다른 구도·색감·표현을 사용하되, 새로움을 위해 주제와 무관한 업종이나 풍경으로 바꾸지 않는다. 별도 비유 설명이 있어야 연결되는 꽃시장·연극·공장 같은 장면은 피한다.

실제 서비스 화면이나 사용 결과를 보여줄 때는 확인된 자료를 사용한다. 생성한 가상 화면을 공식 화면처럼 표현하지 않는다.

제목과 게시글 전체의 핵심에 가장 잘 맞는 표지를 별도로 1장 생성한다. 종전 표지와 다른 토스 스타일의 명료한 구성과 큰 한글 제목을 사용하고 대표 이미지로 설정한다.

## 6. 인포그래픽과 모션그래픽

$handdrawn-infographic으로 게시글 전체의 핵심을 파스텔 손그림 인포그래픽으로 실제 제작하여 30초 요약 바로 아래 배치한다. 설명을 길게 복사하기보다 비교·관계·판단 기준을 한눈에 보여준다.

$workflow-motion으로 글에서 설명하는 실제 활용 과정이나 조건별 판단 흐름을 손그림 모션그래픽으로 실제 제작한다. 내부 집필·게시 절차를 그리지 않는다.

입력, 단계, 수행 주체, 결과, 필요한 분기와 되돌림을 본문에 맞게 연결한다. 근거 없는 자동 처리나 보장된 결과를 만들지 않는다. 마지막에는 전체 흐름을 읽을 정지 구간을 둔다.

정지 이미지의 한글·수치·화살표·잘림·모바일 가독성을 확인한다. 모션은 실제로 한 번 재생하여 흐름과 읽을 시간을 확인한다. 설명 정보를 추가하지 않는 장식 효과는 줄인다.

## 7. 광고·고지문·작성자 댓글

본문의 모든 이미지에 표지·인포그래픽을 포함하여 관련 상품의 제휴 링크를 연결하고, 모션그래픽에도 연결한다. 검증된 네이티브 이미지 링크 도구만 사용한다.

목록과 홈의 썸네일은 기존처럼 게시글로 이동하게 유지한다.

관련 제품 광고배너를 상단·중단·하단에 배치한다. 본문에는 이 배너와 이미지·모션에 연결한 제휴 링크, 필수 고지문 외에 별도의 상품 광고 문장이나 텍스트 제휴 링크를 넣지 않는다. 정보 확인용 버튼과 출처 링크는 허용한다.

게시글 시작 순서는 다음과 같이 한다.

1. 실제 본문의 도입문 1~2문장
2. 쿠팡 파트너스 고지문
3. 상단 쿠팡 광고배너
4. 나머지 본문과 표지·30초 요약 등

아래 고지문을 도입문 다음, 상단 쿠팡 배너 바로 위에 HTML 편집으로 배치한다. 앞뒤 콘텐츠와 간격을 둔다.

“이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.”

고지문은 볼드·배경색 없이 평문으로 읽기 쉽게 표시한다. 지나치게 작거나 흐리게 만들지 않는다. 목록 요약을 바꾸기 위해 고지문을 숨기거나 이미지로 대체하지 않는다.

작성자 상품 댓글은 한 개로 정리하고, 상품마다 아래 세 가지를 포함한다.

- 이 글에서 선정한 이유를 친절하게 설명하는 한 문장
- 텍스트 제휴 링크

선정 이유는 ‘이 글을 읽는 사람이 어떤 상황에서 참고하거나 사용할 수 있는가’를 구체적으로 설명한다. 막연한 추천, 구매 압박, 확인되지 않은 효과나 직접 사용 경험을 쓰지 않는다. 상품명·이유·링크 외의 긴 광고 설명은 덧붙이지 않는다.

기존 작성자 상품 댓글이 있으면 중복 생성하지 않고 갱신한다. 본문 고지문을 확인한 뒤 작성자 댓글의 중복 고지문만 삭제한다. 독자 댓글은 수정하지 않는다.

## 8. 편집과 저장

게시봇 프로필 하나, 편집창 하나에서 진행한다.

전반에는 네이티브 편집기로 본문 작성, 이미지 업로드, 이미지·모션의 제휴 링크, 태그, 분류, 대표 이미지 설정을 완료한다.

후반에는 HTML 편집으로 광고배너·고지문·필요한 서식만 보정한다. 기존 이미지 코드는 보존한다. 작성자 상품 댓글은 게시 후 댓글창에서 처리한다.

기존에 확인된 성공 경로를 우선 사용하고, 정상 작동하는 단계의 도구나 방식을 불필요하게 바꾸지 않는다.

같은 이슈가 3회 이상 반복되고 해결되지 않으면, 원고·자산·오류 기록을 보존하고 기존 편집창을 닫은 뒤 새 편집창 하나에서 처음부터 다시 입력한다. 문제와 무관한 확정 원고와 이미지는 재사용한다.

저장 여부가 불확실한 경우에는 편집기를 다시 열어 재게시하기 전에 기존 글의 생성·저장 상태부터 확인한다.

## 9. 최소 검증과 완료 기록

검증 최소화와 빠른 게시를 우선한다. 주제 선정 때 근거와 상품 관련성을 확인하고, 제작 중 발견한 오류는 해당 부분만 고친다.

저장 직전에는 최종 확인을 한 번으로 묶는다. 본문 조건·수치, 상품 관련성, 이미지 설명력, 제목과 본문 크기, 도입문·고지문·배너 순서, 이미지 링크, 대표 이미지, 분류·태그를 확인한다. 이미 통과한 검사는 변경이나 새 문제가 없으면 반복하지 않는다.

최종 확인 한 번 → 저장 한 번 → 실제 게시 결과 확인으로 마무리한다.

실제 게시물에서 핵심 배치와 링크를 확인하고, 상품 이름·선정 이유 한 문장·제휴 링크가 포함된 작성자 댓글 한 개를 처리한다.

홈·목록 요약에 고지문 대신 실제 도입문이 나타나는지 확인한다. 웹과 티스토리 앱의 확인 결과를 구분한다. 앱 화면을 직접 확인할 수 없거나 갱신이 지연되면 미확인 상태로 기록하고, 웹 확인만으로 앱까지 성공했다고 보고하지 않는다.

완료 기록에는 게시 URL, 주제·상품 선정 이유, 사용한 편집 순서, 실제 확인 결과, 소요 시간, 남은 문제가 있다면 그 내용을 남긴다.

실제로 성공한 경로에만 ‘성공 경로’ 태그를 붙인다. 실패한 방법은 실패 원인과 재시도하지 않을 조건을 별도로 기록한다. 다음 시도에서는 현재 환경에 맞는 성공 경로를 선택한다.

상품 옵션 확인, 이미지 생성 완료, 서식 준수만으로 전체 품질을 통과시키지 않는다. 상품이 독자에게 필요한 이유, 이미지가 설명하는 내용, 글을 읽고 할 수 있는 행동까지 확인했을 때 완료로 보고한다.

## 실행 해석

댓글 항목 목록에는 두 줄만 있으나, 같은 7항의 ‘상품명·이유·링크’와 9항의 명시 조건을 함께 적용하여 상품 이름, 선정 이유 한 문장, 제휴 링크의 세 가지를 포함한다. 사용자 원문은 위에 보존했다.

## 성공 경로와 재발 방지

1. 현재 목표·현재 작성기·최근 성공 경로를 구분한다. 예전 종료 지시를 새 작성기에 재적용하지 않는다.
2. 현재 프로필과 실제 빈 작성기를 확인하고 새 제목·문단·번호 제목·태그·IT 카테고리를 네이티브로 입력한다.
3. 빠른 문단 입력이 일부 경계를 합쳤을 때, 관찰된 세 경계만 커서-before→Return으로 보정한다. 전체 본문을 다시 쓰지 않는다.
4. 각 이미지 마커를 먼저 삭제한다. 관찰된 사진 메뉴를 누르기 전에 filechooser를 대기하고 정확한 파일을 넣는다.
5. 새 IMAGE를 클릭하고 ALT를 저장한다. ALT 저장 후 이미지 선택과 도구가 바뀔 수 있으므로 최신 UI에서 해당 IMAGE를 다시 선택한 뒤 IMAGE 링크 도구를 연다. 오래된 도구 ID로 클릭하면 다른 메뉴가 열릴 수 있다. 이것을 잠긴 Mac이나 작성기 장애로 오판하지 않는다.
6. 표지 대표 배지의 체크를 확인한다. 현재 표시 소스를 네이티브 전체 선택·복사로 읽어7개 native image code를 메모리에서만 보존한다. HTML 모드와 기본 모드 전환은 클릭이 대기 중일 때 mode-confirm helper로 확인창을 처리한다.
7. 배너3·요약표·버튼4와 서식을 마무리한다.7개 native code를 그대로 보존한 뒤 제목4/본문21/고지1/이미지10(배너 포함)을 실제 작성기에서 한 번 점검한다.
8. 공개·현재·IT 인터넷을 확인하고 저장 시도 기록을 남긴 후 신규 공개 발행을 한 번만 누른다. 저장중 상태는 성공으로 간주하지 않고 실제 관리자와 공개 페이지로 확인한다.
9. 실제 수정 링크에서220번을 확인하고 작성자 댓글을 한 번 등록한다. 댓글 개행은 DOM에서 공백으로 정규화될 수 있으므로 실제 고유 문장으로 대상을 읽고 재등록하지 않는다.
10. 공개 페이지의 전면 광고/초점·AX 인덱스 차이와 상대 이미지 URL은 표면별 문제로 다룬다. 최신 네이티브 스크린샷/좌표 스크롤과 상대URL의 기준 origin으로 읽기 작업을 마무리한다. 글 재저장으로 대응하지 않는다.

Partners 코드 복사 버튼의 클립보드에는 이전 HTML이 남아 있었다. 실제 현재 배너의 공개 코드만 표시된 DOM에서 읽었고 이전 signed native 코드를 파일에 쓰지 않았다. 미디어 서명URL·인증 키는 성공 기록에 포함하지 않는다.

## 실제 성공한 편집 순서

1. 게시봇 Chrome 프로필 하나에서 새 네이티브 작성기 하나를 열었다.
2. 확정 원고와 제목을 네이티브로 입력하고 경제 분류와 태그 6개를 설정했다.
3. 표지 → 손그림 인포그래픽 → 주요 절 이미지 3장 → 22초 GIF 순으로 네이티브 파일 선택기로 업로드했다.
4. 업로드 직후 네이티브 이미지 전용 링크 도구(mceu_46)와 대체 텍스트 도구(mceu_47)로 각각 제휴 링크·ALT를 설정했다. 본문 링크 도구를 대체 사용하지 않았다.
5. HTML 전환 확인창을 처리하고 실제 이미지 코드 6개를 메모리에 보존했다. 고지문·광고배너 3곳·요약 배경·제목과 본문 크기·정보 버튼만 보정했다. 이미지 코드는 변경하지 않았다.
6. HTML 원문 붙여넣기를 비교한 뒤 기본 모드로 돌아와 한 번의 최종 확인 묶음으로 링크·서식·배치·분류·태그를 확인했다.
7. 발행 설정의 표지 미리보기가 의도한 표지임을 확인하고 공개 발행을 한 번 실행했다. 저장 중에는 재클릭하지 않았다.
8. 글 관리의 새 항목과 실제 게시물의 수정 URL에서 post 231을 확인했다. 실제 게시물에서 배치·링크를 확인한 뒤 작성자 댓글 한 개를 등록했다.

## 확인 결과

- 시작 순서: 실제 도입문 → 평문 고지문 → 상단 쿠팡 배너 → 표지 → 30초 요약 → 손그림 인포그래픽.
- 고지문: 14px, 글자 굵기 400, 투명 배경. 요약: 노란 배경 rgb(255,247,214). 주요 절 제목: 23px/700. 본문: 16px/400. 절마다 본문 핵심 문장 하나씩 총 3개만 굵게 표시.
- 수동 쿠팡 배너: 상단·중단·하단 정확히 3개. HTML 카드 배너로 상품명과 이동 버튼을 표시했다. 별도 상품 홍보 문장·텍스트 제휴 링크는 일반 본문에 없다.
- 표지·인포그래픽·절별 이미지 3개·모션 총 6개 모두 동일하게 검토한 상품의 제휴 링크가 네이티브 이미지 코드에 연결됐다. ALT와 실제 로딩을 확인했다.
- 손그림 인포그래픽의 기한 기준을 ‘지급정지 요청 후’로 보완하고 한글·숫자·화살표를 점검했다.
- GIF는 실제 업로드된 GIF 주소를 브라우저에서 재생해 강조 구간 변화와 전체 흐름을 확인했다. 배경 탭의 화면 관찰은 같은 프레임에 머물러 마지막 구간 판단에 부적합했다. 네이티브로 해당 탭을 활성화하자 전체 패널이 함께 강조되는 마지막 정지 구간을 확인했다. 최종 5초 정지 구간을 포함하며, 22초는 설명 길이이고 실제 금융 처리 시간이 아니다.
- 작성자 댓글: 상품명 + 선정 이유 한 문장 + 제휴 URL, 한 개 등록 확인. 중복 고지문 없이, 독자 댓글 수정 없음.
- 웹 홈: 표지가 나타나고 썸네일 링크가 게시글로 연결된다. 요약의 첫 부분이 고지문 대신 실제 도입문으로 시작한다. 원시 요약 텍스트의 뒤쪽에는 고지문이 포함되지만 표시되는 첫 부분은 도입문이다.
- 앱 홈·목록: 직접 확인할 수 없어 미확인. 앱까지 성공했다고 주장하지 않는다.
- 본문에는 기존 스킨·플랫폼의 자동 광고가 별도로 보일 수 있다. 수동 쿠팡 배너 3개와 자동 광고 수량을 구분한다. 글로벌 광고 설정은 변경하지 않았다.

## 오류와 재발 방지

- 네이티브 AX 차분에서 첨부 버튼을 찾으려다 한 번 실패했다. 전체 AX 관찰로 바꾸어 해당 버튼을 찾았고 해결했다. 확정 원고나 이미지는 재생성하지 않았다.
- 최종 읽기 확인 중 상위 문서에서 iframe.contentDocument를 읽는 방법이 지원되지 않았다. 프레임 로케이터 안의 본문 DOM을 읽어 해결했다. 이 읽기 오류는 작성기 잠금 증거가 아니다.
- 게시 후 역할 기반 이미지 조회는 이름 없는 DOM 표현 때문에 실패했다. 실제 이미지 ALT를 확인한 DOM 읽기로 조회했다. 같은 실패 방식은 반복하지 않는다.
- 모바일 viewport 요청은 실제 window.innerWidth=1200으로 남았다. 모바일 브라우저 화면 성공으로 기록하지 않고 기존 크기로 복원했다. 저장된 홈 화면 파일은 web으로 명명했다.
- 특정 상품 페이지의 접근 거부를 Mac 잠금·로그인 실패로 추정하지 않는다. 상세 페이지 접근 우회·반복 후보 탐색 대신 API와 공개 서지 자료를 사용하고 확인 범위를 명시한다.
- 불필요한 복합 상품 검색은 물티슈·배터리·무관한 책을 반환했다. 관련성을 통과시키지 않았다. 이번 성공 검색어는 핵심어 ‘보이스피싱’이었다.
- 동일 작성기 이슈가 해결되지 않은 채 3회 반복된 경우는 없었다. 그런 경우에는 원고·자산·오류를 보존하고 기존 작성기를 닫은 뒤 새 네이티브 작성기 하나에서 재입력한다.

## 다음 시도에 재사용할 것

새 네이티브 작성기 하나 → 확정 원고 → 각 업로드 직후 이미지 전용 링크·ALT → HTML 후반 서식만 한 번 → 기본 모드 최종 확인 → 대표 표지 발행 미리보기 → 공개 발행 한 번 → 실제 글·작성자 댓글·웹 홈 확인. DOM 차분으로 버튼이 빠지면 전체 AX를 읽고, 실제 증거 없이 ‘Mac이 잠겼다’고 판단하지 않는다.

남은 확인 한계는 앱 화면, 모바일 viewport 재현, Coupang의 실시간 상세 재고·배송이다. 게시·댓글·웹 확인 경로의 성공과 이 한계를 구분한다.

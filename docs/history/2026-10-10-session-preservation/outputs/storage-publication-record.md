## 선정 이유와 자료 한계

가족 구독의 용량 합산, 파일 공개 범위, 정리 전 독립 사본이라는 생활 질문에 답한다. 최근 홈의 post225~232와 다른 저장공간 주제다. 계절과 무관하게 파일 보관 판단에 활용할 수 있다는 편집 판단이며, 검색량·미래 인기의 확정적 측정으로 표현하지 않았다.

[Microsoft 변경 안내](https://support.microsoft.com/en-us/onedrive/changes-to-microsoft-365-storage)를 실제 브라우저에서 확인했다. 신규/업그레이드 적용일 2026-10-08, 기존 갱신 2027-05-02 이후라고 표시한다. [공식 용량 초과 안내](https://support.microsoft.com/en-gb/onedrive/my-onedrive-says-it-s-full)는 10-07/04-01로 달라, 본문에 두 자료의 차이와 계정별 적용 미확인을 남겼다. 발표·수정 시각을 공개하지 않아 36시간 이내 발표라는 엄격한 신선도는 확인하지 못했다. 적용 날짜와 발표 날짜를 혼동하지 않았다.

[파일 주문형](https://support.microsoft.com/en-us/onedrive/save-disk-space-with-onedrive-files-on-demand-for-windows), [파일 삭제](https://support.microsoft.com/en-us/onedrive/delete-files-or-folders-in-onedrive) 안내로 온라인 전용/로컬 다운로드/동기화 삭제 차이를 확인했다. 0.9+0.6+0.2=1.7TB 사례는 가정으로 명시했다. 실제 사용자 파일·구독을 변경하거나 직접 사용한 후기라고 쓰지 않았다.

## 성공 경로: 실제 실행 순서

1. Chrome 게시 프로필1에서 새 관리창→저장된 카카오 계정 간편 로그인→글쓰기. 이전 임시글 복원 확인은 취소했다.
2. 새 기본모드 작성기1개에 확정 원고를 네이티브 HTML 붙여넣기. 분류·태그 완료.
3. 표지, 인포그래픽, 절별 정지3장, 손그림 GIF 총6개를 네이티브 업로드. 이미지 전용 mceu_46 링크 도구와 mceu_47 대체텍스트 도구로 모두 연결했다. 기존 글 수정/사용자 작성창 닫기 없음.
4. 표지는 실제 화면을 위로 스크롤→표지 클릭→대표 배지 클릭. 발행 설정 화면에서 표지를 확인했다.
5. HTML모드에 한 번 들어가 필요한 서식·고지·배너만 수정했다. 원본 이미지 코드6개를 임시 표식으로 보호한 뒤 원래 코드로 복원했고, 각 코드가 완전히 같은지 확인했다. 네이티브 인포그래픽이 표 마지막 셀에 들어간 부분은 표의 원문을 복원하고 기존 인포 코드를 요약 다음 위치로 옮겼다.
6. 기본모드 복귀→최종 묶음 확인1회→완료→공개/IT 인터넷→공개 발행1회. 저장 중에는 다시 누르지 않고 글 관리에 새 제목이 생성되는지 확인했다.
7. 실제 게시물→작성자 댓글1회→웹 홈 도입문과 대표 표지 확인→GIF 실제 재생 관찰. 게시물 관리 링크에서 id233을 확인한 뒤 숫자 URL로 열었다. 작업 작성창은 닫았다.

- 고지문 평문/배경 투명/14px. 주요 제목23px/700, 긴 본문16px/400. 절별 강조3개.
- 노란 요약 배경 rgb(255,247,214), 표 내용 복구, 인포그래픽 바로 다음 배치.
- 수동 쿠팡 상품 배너3개(상·중·하). 기존 자동 애드센스/애드핏은 동적 노출되므로 전체 광고 개수가3개라는 뜻은 아니다. 스킨 수익 설정을 변경하지 않았다.
- 이미지·모션6개 대체텍스트와 동일 제휴 링크 확인. 단독 상품명/텍스트 제휴 광고 문장은 본문에 추가하지 않았다. 공식 정보 버튼4개와 관련 글232 버튼1개.
- 웹 홈 첫 카드의 보이는 요약이 실제 도입문으로 시작하고 고지문으로 도배되지 않음. 표지 썸네일의 링크는233 게시글로 연결됨.
- 작성자 댓글1개 저장 완료 및 상품명·이유·링크 확인.
- 정지 이미지 한글, 숫자,6명·파일 비공개 구조 검사. 실사 생성 이미지는 공식 화면/실상품사진이 아니라는 표시 포함.
- GIF220프레임,22초, 마지막5초 전체 흐름 유지. 실제 게시된 GIF를 브라우저에서 열고 구독확인→다운로드·복사→복사본열기 등 단계 강조 변화와 반복 재생을 관찰했다. 단계·오류 되돌림·유지 분기와 큰 한글은 본문에 대응한다.
- 편집기 전체 표시 텍스트는3876자(고지·요약표·버튼·출처·이미지 안내 포함). 약3000자 목표보다 다소 길며 분량 정확 일치로 보고하지 않는다.
- 티스토리 앱: 직접 확인할 수 없어 **미확인**. 웹 성공을 앱 성공으로 확장하지 않았다.

## 실패와 재발 방지

- 없는 ‘상품 검색’ 링크를 클릭해 실패: 현재 페이지의 실제 ‘상품 링크’ 경로를 읽고 선택. 다음에는 옛 메뉴 이름을 가정하지 않는다.
- 제목 입력 시 이전 임시글 복원 대화상자가 막음: 현재 dialog를 취소하고 입력. 새 작성기라도 복원 안내를 먼저 처리한다. Mac 잠금이라고 추정하지 않는다.
- 이미지 선택만으로 화면이 해당 위치에 가지 않음: native 실제 화면 스크롤 후 이미지와 대표 배지를 클릭한다. 키보드 커서 이동을 스크롤 성공으로 보지 않는다.
- HTML 보정 전 코드 보존 검사2회 실패: 인포가 표 안에 삽입돼 요약 끝 계산이 앞선 표지까지 포함되는 것이 원인. 원본을 건드리지 않고 위치를 바로잡고, 이미지 코드는 표식으로 보호한 뒤 복원해 통과했다. 실패한 수정본은 편집기에 붙이지 않았다.
- 표 바로 다음 이미지 삽입: 현재 커서가 표 셀에 남을 수 있다. 다음에는 업로드 직후 원래 표 셀의 문장과 표시용 삽입표식이 사라졌는지를 해당 부분만 확인한다. 이미지는 재생성/재업로드하지 않고 원본 코드를 보존하여 위치만 보정한다.
- 동일 이슈3회 미해결 상태에는 도달하지 않았다. 도달하면 원고·자산·오류를 보존하고 현재 소유 작성기만 닫아 새 작성기1개에서 재입력한다.

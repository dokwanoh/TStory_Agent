3. 표지·인포그래픽·절별 이미지3장·GIF를 네이티브 업로드했다. 각각 네이티브 이미지 링크 도구로 API 제휴 단축링크를 연결했다.

5. 후반 HTML 모드에서 고지·배너3개·23px 제목·16px 본문·요약 배경·표 머리행·버튼4개만 보정했다. 기존 이미지 코드6개가 정확히 보존됨을 확인했다.

7. 관리 목록에 생성된 글을 먼저 확인하고 해당 게시물로 이동했다. 수정 링크의 post238과 공개 본문을 확인했다. 재게시하지 않았다.

## 실패 원인과 재발 방지

- DOM 이미지 클릭은 링크/커서 동작으로 이동하여 실제 표지 선택과 달랐다. 재시도 조건: 화면에 이미지가 보이지 않는 상태에서 같은 클릭을 반복하지 않는다. 실제 네이티브 스크롤 후 이미지 좌표 선택·대표 배지 클릭이 성공했다.
- 네이티브 붙여넣기에서 표 헤더가 본문으로 분리됐다. HTML 후반 보정 단계에서 머리행을 복원한다. 전체 원고를 다시 입력할 필요가 없었다.
- 이미지 링크 창의 대체텍스트는 이미지 alt와 다르다. 표지 alt는 별도의 네이티브 대체 텍스트 도구로 입력했다. 입력 후 대화상자 이름이 바뀌므로 변경 전 이름의 선택자를 반복 사용하지 않는다.
- HTML 모드의 텍스트박스 마지막 항목은 태그다. 관찰된 HTML textarea를 지정하여 전체 선택·복사·네이티브 붙여넣기한다. 원문·이미지 서명 URL은 로그로 출력하지 않고 메모리에서 보존한다.
- 모드 전환 확인 창은 전환 클릭과 함께 처리한다. 확인 창이 나타난 뒤 전환 클릭을 반복하지 않는다.
- 페이지의 불러오지 않은 이미지는 스크롤 전 lazy-loading 상태였다. 실제 위치로 스크롤한 뒤 로딩됨을 확인했다. 이를 업로드 실패나 Mac 잠금으로 판단하지 않는다.
- 동일 미해결 문제가3회 반복된 경우는 없었다. 다음 작업에서도3회 반복되면 원고·자산·기록을 보존하고 기존 작성창을 닫은 뒤 새 작성창 하나에서 재입력한다.
- 생성 결과·광고 iframe 전체 HTML은 불필요하게 크다. 이후에는 파일 경로·작은 메타데이터만 출력하고 광고 개수·공개 단위 ID만 조회한다.

이번 기록의 ‘성공 경로’는 post238의 실제 공개·댓글·웹 확인까지 성공한 순서만 뜻한다. 앱 확인이나 인기 수치까지 성공했다는 의미가 아니다.

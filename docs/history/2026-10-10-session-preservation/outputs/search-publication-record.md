## 주제와 상품

독자 질문은 ‘구글 검색 방문자가 줄면 글부터 지워야 할까?’입니다. 결론은 날짜·유입 경로와 검색 실적을 나누어 보고 확인된 문제부터 고친다는 것입니다. 구글 공식 상태판에서 9월 스팸 업데이트의 완료 시각 10월8일01:00PDT와 공지01:37PDT를 확인했습니다. 한국시간17:00/17:37로 조사 약8시간 전,36시간 기준 안입니다. 시작9월24일09:15PDT는 한국9월25일01:15입니다.

세계·모든 언어의 검색 결과에 적용된다는 공식 범위가 검색 유입을 받는 개인 블로그·소규모 사이트 독자의 현재 관심 근거입니다. 검색량·성장률을 측정하지 않았으며 향후 관심은 실용성에 대한 추론입니다. 최신 웹 홈8글과 로컬 원고·완료기록에서 같은 점검 질문이 발견되지 않았습니다. 특정 사이트의 감소 원인이나 새 판별 기준은 발표에서 확인되지 않아 단정하지 않았습니다.

API 검색은 HTTP200/rCode0이며 키는 키체인 내부에서만 사용했습니다. 상품 API의 SEO 질의가 반환한 물티슈·건전지 등 무관 후보는 제외했고 정상 상세 페이지가 열린 SSD도 본 주제 관련성 부족으로 제외했습니다.

본문 미디어·배너·댓글은 동일 상품 옵션의 API 제휴 링크를 사용합니다. 본문에서 상품명·별도 텍스트 광고를 늘리지 않았습니다. 상품명·이유·URL은 작성자 댓글1개에 들어 있습니다. 댓글 URL은 텍스트로 표시되며 이 스킨에서 클릭 가능한 a 태그로 변환되지는 않았습니다. 본문 미디어와 배너는 실제 클릭 가능한 a 링크입니다.

## 성공 경로: 새 네이티브 작성기에서 마감

1. 현재 목표는 이전 날씨 제한을 해제한 새 요청으로 등록했습니다. 과거 post229를 새 목표 결과로 재사용하지 않았습니다.
2. 근거·상품 관련성을 통과한 뒤 원고와 표지·인포그래픽·3절 이미지·22초GIF를 제작했습니다. 내장 imagegen으로 정지 이미지5개를 개별 생성하고, 검증된 Swift AppKit/ImageIO 렌더러로 모션을 제작했습니다. 새 search-workflow-frame 이름으로 기존 자산을 보존했습니다.
3. 게시봇 Chrome1에서 새 작성기959319766 하나를 열었습니다. 깨끗한 작성기에 확정 본문을 네이티브 HTML 붙여넣기로 입력하고 IT·6태그를 설정했습니다. 사진·링크 작업은 네이티브 기본모드에서 진행했습니다.
4. 매 미디어마다 최신 전체AX의 본문 번호로 자리표식을 선택·삭제했습니다. 사진 메뉴 앞에서 filechooser 대기를 먼저 시작하고 실제 사진 메뉴를 클릭해 지정 파일을 업로드했습니다. 실제 이미지 링크 팝업에 동일 상품URL을 입력했습니다. 6개 모두 성공했습니다.
5. ALT는 최신 전체AX에서 팝업 입력·확인 번호를 얻어6개 전부 완료했습니다. 표지를 선택하고 실제 대표 배지를 클릭했으며 공개 설정의 표지 미리보기로 대표 이미지를 확인했습니다.
6. 후반 HTML 모드 전환과 기본모드 복귀는 mode-confirm의 확인창 동시 처리 경로를 재사용했습니다. 현재 작성기의 실제 네이티브 이미지 코드6개는 메모리에서 원문 그대로 보존했습니다. 고지·상중하배너3개·요약배경·제목/본문/버튼 서식만 보정했습니다.
7. 소스 입력은 최신 실제 소스 칸을 클릭→전체선택→paste(null) 순서로 교체했습니다. 전체 복사값15,436자가 준비한 보정본과 정확히 일치했고 이미지 코드6개 보존·배너3개를 확인했습니다. 서명된 이미지 코드는 파일로 저장하지 않았습니다.
8. 최종 확인 한 번에 본문·가정 수치·3개 핵심 강조·모든 이미지 링크·분류·태그·대표·고지와배너·요약 배경을 묶었습니다. 현재·공개·댓글허용·IT인터넷으로 공개 발행1회했습니다. 저장중에는 재클릭하지 않고 관리자218글과 새 제목을 확인했습니다.
9. 공개 게시물에서 내용·수정링크230·발행시간을 확인하고, 작성자 댓글1개를 등록해 실제 표시를 확인했습니다. 웹 홈의 도입문 시작과 썸네일→글 이동을 확인했습니다. 실제 성공한 이 순서에만 성공 경로 태그를 붙였습니다.

## 실제 게시 검증

- 도입문→평문 고지→상품 광고배너→표지. 고지14px/400/투명, 본문16px/400, 제목23px/700.
- 30초 요약 #fff7d6 배경, 바로 아래 인포그래픽. 주요 절3개, 절마다 핵심 강조1개.
- 네이티브 미디어6개 모두 ALT·동일 상품 제휴 링크. 본문을 순서대로 스크롤한 뒤 이미지9개(미디어6+배너3) 전부 로딩했습니다. 화면 밖 loaded=false는 지연 로딩이었으며 재업로드하지 않았습니다.
- 수동 관련 상품 배너는 정확히 상단·중단·하단3개. Partners 공식 배너 생성 도구는 기존 창 새로고침과 새 홈페이지 창 모두 빈 화면이었습니다. 실제 확인한 상품 사진+API 제휴 링크로 HTML 상품 배너를 구성해 요구된3곳에 배치했습니다. 공식 배너 생성 성공으로 기록하지 않습니다. 기존 스킨 자동 애드센스·애드핏은 별도입니다.
- 공식 정보 버튼3개, 직접 관련된 post223의 AI문장 조건 대조 버튼1개. 광고 외의 별도 상품 홍보 문장 없음.
- 모션은 게시된 실제 HTTPS GIF를 Chrome 이미지 뷰어에서 열어 단계 강조→전체 정지→반복 시작을22초 이상 관찰했습니다. 분기 두 경로와 조건은 항상 남아 있고 최종5초 전체 읽기 구간을 확인했습니다. 22초는 설명 시간이며 실제 반영 시간이라고 쓰지 않았습니다.
- 웹 홈 요약은 ‘구글 검색에서 들어오는 방문자가 줄었다면’으로 시작합니다. 보이는 요약에 광고 고지 대신 실제 도입이 나옵니다. 홈 표지는 생성 표지이며 링크는 글입니다.
- 작성자 댓글1개에 상품명·친절한 선정 이유·API URL 표시. 본문 고지 중복 댓글은 없음. 독자 댓글 수정 없음. 중첩된 같은ID 댓글컨테이너2개를 댓글2개로 오인하지 않았습니다.

## 실패와 재발 방지

- ALT 입력 후 차이AX에서 변경되지 않은 확인 버튼을 찾으려 한 호출1회가 실패했습니다. 이미 입력된 팝업을 최신 전체AX로 읽고 확인만 완료했습니다. 다음 이미지 ALT helper도 전체AX로 바꿔5개를 연속 완료했습니다. 업로드를 반복하지 않았습니다.
- 소스 칸 전체선택 뒤 특정번호로 paste하면 선택이 풀려 입력이 예상대로 반영되지 않는 문제가 있었습니다. 실제 소스 클릭→전체선택→paste(null)→전체복사 대조 경로로 해결했습니다. 기존 소스가 보인 상태를 보정 성공으로 보고하지 않았습니다.
- 공개 이미지 role 선택1회가 실패해 동일 접근을 반복하지 않고 관찰된 .contents_style img의 실제 ALT로 찾았습니다. 모션을 재생했습니다.
- 댓글 컨테이너는 동일ID가 중첩되어 strict locator가2개로 해석됐습니다. 현재 실제2컨테이너의 텍스트를 읽어 동일 댓글1개의 중첩임을 확인했습니다. 댓글 재등록 없음.
- 작성기에서 같은 미해결 문제가3회 반복되는 경우는 없었습니다. 새 작성기를 다시 여는 규칙의 발동 조건에 해당하지 않았습니다. 이번 작업에서 Mac 잠금을 주장하거나 사용자에게 탭 종료를 맡기지 않았습니다.

## 확인 한계와 증거

티스토리 앱과 실제 휴대전화 화면은 직접 확인하지 못했습니다. 앱 요약은 미확인이며 웹 성공을 앱 성공으로 확대하지 않습니다. 이미지의 한글·화살표·잘림은 시각 검토했고 공식서비스 가상 화면을 만들지 않았습니다. 달력 사진과 점·포인터 그림은 개념 삽화이며 실제 발표 날짜·실측 수치가 아닙니다. 첫 사진 ALT에도 실제 업데이트 날짜 표시가 아님을 명시했습니다.

별도 Partners 공식 배너 도구의 빈 화면 원인은 확인되지 않았습니다. 이를 Mac 잠금·인증 만료·전체 상품 서비스 중단으로 추정하지 않았고, 확인된 실제 상품 사진과 API 링크의 배너 경로를 사용했습니다.

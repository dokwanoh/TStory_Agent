## 성공 경로: 현재 환경의 순서

1. 게시봇 Chrome 프로필 하나, 작성기 하나를 유지하고 관리자 최근 글·post223 스타일을 확인한다.

3. 짧은 한국어 원고와 설명력 있는 자산을 제작한다. 가정 예시는 원문·요청·예시 결과·대조할 조건을 연결한다.
4. 네이티브에서 IT 분류, 원고, 태그 6개, 자산 업로드 7개, ALT, 이미지 링크 도구의 제휴 URL, 대표 표지를 끝낸다. 업로드 함수에 현재 글 디렉터리·ALT·제휴 URL을 명시한다.
5. 모드 변경은 클릭 진행 중 confirm을 처리하는 `mode-confirm.mjs` 경로. ‘confirm 때문에 클릭 중단’ 반환에도 실제 변환된 모드를 관찰하고, 확인된 전환을 다시 클릭하지 않는다.

## 실패·보정과 재시도하지 않을 조건

- **일반 iframe 배너:** 공식 원본에는 `referrerpolicy="unsafe-url"`이 있었지만 공개 DOM에서는 없어졌다. 편집기 상품 프레임은 보이고 공개 세 영역은 비었다. 속성 제거와 빈 표시의 인과관계는 단정하지 않는다. 공식 블로그용 태그로 해당 세 영역만 바꾸자 공개 로딩 3개 성공. 편집기 미리보기만으로 일반 iframe을 성공 처리하거나 같은 코드를 반복 저장하지 않는다.
- **최초 표지:** API 잔액과 채팅 사이 등호가 의미를 혼동시켰다. 이미지 편집으로 구분선으로 바꾸고 최종본 업로드. 원본은 실패 변형이며 성공 표지로 재사용하지 않는다.
- **넓은 상품 검색:** 묶음·무관 상품이 섞인 응답은 관련성 통과가 아니다. 실제 단행본 옵션과 독자 활용이 확인된 결과만 사용한다.
- **/224 탐색 대기 시간 초과:** 현재 URL·제목·수정 링크·댓글은 정상 확인. 탐색 대기 시간 초과를 저장 실패로 간주해 재게시하지 않는다.
- **뷰포트 밖 스크롤 좌표 1회:** 입력 미적용. 현재 스크린샷의 유효 좌표로 진행했고 본문 변화 없음. 오래된 화면 크기의 좌표를 재사용하지 않는다.
- 동일 해결 불가 문제가 3회 연속 발생한 사례는 없음. 실제 조건 발생 때만 확정 원고·자산·오류를 보존하고 기존 작성기 닫힘 확인 후 새 작성기 하나에서 재입력한다.

# 독자 점검 흐름

source: outputs/search-traffic-article.md 최종 원고
message: 검색 유입 감소를 바로 삭제로 연결하지 않고 기록과 확인된 문제로 다음 행동을 정한다.
nodes: N1 날짜/경로 대조, N2 노출/클릭/페이지 비교, N3 기술/보안/정책/내용 문제판단, N4 해당 문제 수정·기록, N5 미확인시 관찰, N6 기간뒤재비교. 모든 수행 주체는 독자. 입력은 자기 사이트의 방문·검색 실적과 공식공지. 출력은 좁힌 문제 또는 관찰 기록.
edges: N1→N2→N3는 본문 1~3절의 점검 순서. N3→N4 조건문제있음, N3→N5 조건문제미확인. N4/N5→N6 기록후재비교. 글쓰기만으로 기술 문제가 해결되거나 순위가 회복된다는 화살표는 없다. 실제 서비스 처리속도·자동화·보장은 없다.
start:N1, ends:N4/N5의 다음관찰N6. 수동조치/색인 세부검사를 N3로 묶었다. 다음재비교를 자막으로 표현하며 자동원인확정 종료는 만들지 않는다.
timeline:0~3N1,3~6N2,6~9N3,9~12문제있음수정,12~15미확인관찰,15~17기록뒤재비교,17~22전체정지.

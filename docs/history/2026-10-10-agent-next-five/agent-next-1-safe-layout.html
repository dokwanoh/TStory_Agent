Windows에서 AI에게 반복 업무를 맡겨보고 싶었다면 Hermes Agent의 Microsoft Store 진입이 반가운 소식이에요. 설치 경로는 쉬워졌지만, 사용할 AI와 비용을 정하고 작은 작업의 결과를 확인하는 과정은 여전히 필요합니다.

이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.

1. 익숙한 설치 경로가 생겼어요 🪟

{{section1}}

Hermes는 답변만 보여주는 채팅을 넘어, 연결한 도구로 파일을 읽거나 명령을 실행할 수 있는 AI 에이전트예요. 에이전트는 쉽게 말해 ‘설명한 일을 여러 단계로 수행하는 프로그램’입니다. 어떤 도구가 켜져 있는지에 따라 맡길 수 있는 일도 달라져요.

Nous Research는 공식 계정에서 Hermes Agent가 Microsoft Store에 올라왔고 추천 영역에도 소개됐다고 발표했습니다. 명령어 설치가 낯설었던 Windows 사용자에게는 익숙한 앱 유통 경로가 추가된 셈이에요. 다만 입점만으로 누구나 모든 자동화에 성공한다는 뜻은 아닙니다.

설치 조건은 경로별로 나눠 읽어야 해요. 공식 Windows 안내에서 소스 설치는 Windows 10·11을 지원하지만, 필요한 실행 환경을 함께 담은 MSIX 묶음 패키지는 Windows 11 22H2 이상이 필요하다고 설명합니다. MSIX는 Windows용 앱 포장 형식이고, 22H2는 Windows 11의 버전 이름이에요.

‘Windows 지원’이라는 말만 보고 Store 설치 조건까지 같다고 생각하면 안 돼요. 내 PC의 Windows 버전을 먼저 보고, 공식 안내에서 자신이 사용할 설치 경로를 고르는 것이 출발점입니다. Store 상품의 지역별 노출과 설치 화면까지 직접 확인한 것은 아니어서, 여기서 설치 버튼의 위치나 화면을 재현하지는 않습니다.

업데이트 방법도 다릅니다. Store 패키지는 Microsoft Store로 업데이트하며, 소스 설치용 명령을 그대로 적용하는 방식이 아니에요. 10월 8일 공개된 v0.21.6 릴리스는 당시 Store·데스크톱 묶음 배포가 기존 빌드를 유지한다고 밝혔습니다. 코드 릴리스의 변경 목록과 내 Store 앱의 기능을 바로 동일시하면 곤란해요.

2. 설치·AI 연결·비용은 따로 정해요 🔌

{{section2}}

Hermes 프로그램을 설치하는 것과, 답을 만들어주는 AI 모델을 연결하는 것은 다른 단계예요. 모델은 문장을 이해하고 다음 행동을 고르는 AI의 핵심 부분입니다. 공식 빠른 시작 안내도 설치 뒤에 모델 제공자를 선택하고, 정상 대화가 되는지 확인하도록 구성돼 있어요.

Hermes 자체는 무료 오픈소스 프로그램으로 소개됩니다. 누구나 공개된 코드를 살펴볼 수 있다는 뜻이지, 연결하는 모든 AI와 외부 도구의 이용료가 없다는 뜻은 아니에요. 모델·도구를 어떤 서비스로 쓰는지에 따라 요금과 제공 조건을 따로 읽어야 합니다.

예를 들어 공식 안내에는 Nous Portal 구독으로 모델과 도구를 연결하는 경로, 자신의 제공자 설정을 사용하는 경로, 로컬 모델을 연결하는 경로가 나옵니다. 로컬 모델은 내 컴퓨터 등 직접 관리하는 환경에서 실행하는 AI예요. 앱이 내 PC에 있다는 사실만으로 AI 계산과 모든 자료 처리가 PC 안에서 끝나지는 않습니다.

설치 위치와 자료가 처리되는 위치를 구분하는 것이 핵심이에요. 회사 파일을 맡기려면 사용할 모델 서비스와 도구의 자료 처리 조건, 회사에서 허용한 범위부터 살펴야 합니다. 설치 편의성을 이유로 업무 자료 전체를 연결할 필요는 없어요.

공식 빠른 시작 문서는 정상 대화가 되기 전에는 여러 기능을 추가하지 말라고 안내합니다. 처음에는 간단한 대화를 한 번 이어가보고, 그다음 필요한 파일·명령 도구를 선택하는 순서가 이해하기 쉽겠죠. 에이전트가 할 일을 정확히 설명하는 능력은 설치 메뉴가 바뀌어도 계속 도움이 됩니다.

3. 첫 자동화는 ‘엑셀 세 파일’처럼 작게 📁

{{section3}}

아래는 직접 실행한 결과가 아닌 가정 예시예요. 같은 열 이름을 가진 엑셀 파일 세 개를 하나로 합치고 싶다고 해봅시다. 파일마다 ‘날짜·항목·금액’이 있고, 우리는 원본을 보존한 별도 결과 파일이 필요합니다.

먼저 원본을 복사해 연습 폴더를 만들어요. 다음처럼 요청할 수 있습니다. “이 폴더의 엑셀 파일 세 개를 합치는 방법을 먼저 설명해줘. 원본은 바꾸지 말고 결과는 새 파일로 만들어. 열 이름이 다른 파일은 표시하고, 중복 행은 내 확인 전까지 삭제하지 마.”

AI가 바로 처리 완료라고 말하기를 기다리기보다, 대상 파일과 처리 규칙을 먼저 받는 요청입니다. 원하는 규칙인지 읽고 필요한 실행 단계만 승인하는 접근이에요. 복사본을 만든다는 것은 잘못된 변경의 영향을 줄이는 준비이며, 프로그램의 접근을 강제로 제한하는 보안 설정을 대신하지는 않습니다.

가정한 결과는 ‘합쳐진 파일 하나’와 ‘어떤 파일을 읽었고 무엇을 건너뛰었는지 적은 설명’이에요. 실제 결과는 설정·파일 구조·연결한 모델에 따라 달라집니다. 파이썬 코드가 만들어졌다면 파일을 읽는 부분, 저장 위치, 중복 처리 부분을 나눠 설명해달라고 요청할 수 있어요. 파이썬은 파일 처리나 반복 작업에 쓰이는 프로그래밍 언어입니다.

검토할 차이는 구체적이어야 해요. 세 입력 파일의 제목 줄을 제외한 행 수를 더해 결과와 비교하고, 열 이름·날짜·금액이 유지됐는지 살펴봅니다. 중복을 삭제하기로 했다면 줄어든 행의 이유를 따로 봐야 하겠죠. ‘파일이 생겼다’와 ‘원하는 규칙대로 합쳐졌다’는 서로 다른 확인입니다.

이런 도구는 반복되는 파일 작업이 있고 결과를 비교할 기준을 만들 수 있을 때 써볼 만해요. 반대로 한 번이면 끝나는 간단한 작업, 처리 규칙을 정하지 못한 자료, 회사에서 외부 AI 사용을 허용하지 않은 파일이라면 기존 엑셀 기능이나 승인된 도구가 더 적절할 수 있습니다.

오늘 해볼 행동은 설치부터 한꺼번에 자동화하는 것이 아니라, ‘입력 파일·바꾸지 않을 것·받을 결과·검토 기준’을 네 줄로 적어보는 거예요. 새 설치 경로를 활용할 준비가 됐는지, 내 작업에 에이전트가 필요한지 먼저 판단할 수 있습니다.

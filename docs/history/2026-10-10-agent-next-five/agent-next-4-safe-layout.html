1. 휴대폰은 조종기, 실행 장소는 그대로 PC예요 🖥️

{{section1}}

로컬 에이전트는 사용자의 컴퓨터에서 실행되는 AI 작업자를 뜻해요. Cursor의 이번 원격 제어 기능은 그 작업자를 휴대폰에서 살펴보고 대화를 이어가는 방식입니다.

이를 ‘프로젝트가 휴대폰으로 옮겨 간다’거나 ‘노트북이 꺼져도 서버에서 이어진다’고 이해하면 실제 조건과 달라져요. 실행 중인 컴퓨터는 켜져 있고 인터넷에 연결되어 있어야 합니다.

특히 노트북을 덮고 나가려는 사람에게 조건 하나가 중요합니다. 공식 안내의 깨어 있기 옵션은 전원에 연결하고 덮개를 연 상태가 필요해요. 충전기를 꽂았다는 사실만으로 덮개 조건까지 충족한 것은 아닙니다.

폰에서 보인다고 작업의 실행 장소가 바뀌는 것은 아니에요. 집 PC에서 시작한 작업을 외부에서 읽는다면, 여전히 집 PC의 상태가 그 흐름에 영향을 주는 구조입니다.

이 차이를 이해하면 도구를 고르기 편해져요. 잠깐 자리에서 벗어나 질문에 답하고 싶은지, 컴퓨터를 종료한 뒤에도 별도 실행 환경에서 작업을 지속하고 싶은지에 따라 원하는 방식이 다르기 때문입니다.

이번 기능은 Cloud Agents를 요구하지 않는다고 안내되어 있어요. 그래서 기존 PC 작업에 답하는 기능을 쓰려고 곧바로 클라우드 실행으로 전환할 필요는 없습니다. 다만 다른 방식의 실행 조건이나 비용까지 같다는 뜻은 아니에요.

2. 먼저 PC와 휴대폰을 연결하고, 기존 작업을 이어가요 🔗

{{section2}}

공식 안내의 연결 순서는 iOS 앱을 설치하고 로그인한 뒤, 표시된 컴퓨터를 선택하고 데스크톱에서 승인하는 흐름입니다. 같은 계정의 컴퓨터가 나타나며, 연결한 뒤 기존 로컬 에이전트를 볼 수 있어요.

연결했다고 원하는 수정이 이미 완료된 것은 아닙니다. 연결은 대화를 이어갈 통로를 만든 것이고, 작업의 진행 상태와 결과는 별도로 읽어야 하죠.

가상의 예시로 ‘할 일 목록의 완료 버튼 문구 바꾸기’를 생각해 볼게요. PC에서 이미 에이전트를 실행한 상태이며, 실제 프로그램을 만든 경험이나 이번 기능으로 시험한 결과는 아닙니다.

처음 요청은 ‘완료 버튼을 이해하기 쉽게 바꿔 줘’입니다. 에이전트가 어떤 표현으로 바꿀지 물으면, 휴대폰에서는 ‘버튼 문구만 “완료로 표시”로 바꿔 줘. 항목을 삭제하는 동작은 바꾸지 마’라고 답하는 상황을 상상할 수 있어요.

예상하는 결과는 버튼의 문구가 바뀐 수정안입니다. 실제로 확인할 차이는 글자만 바뀌었는지, 기존 완료 동작이 유지되는지, 관계없는 삭제 동작까지 달라졌는지입니다.

작은 추가 요청도 변경 범위가 보이게 적어 주세요. PC 앞에서 입력할 때와 마찬가지로, 휴대폰에서도 무엇을 바꾸고 무엇을 유지할지가 드러나는 요청이 결과를 살펴보기 쉽습니다.

이 예시에서 휴대폰의 역할은 막힌 질문에 답하는 것입니다. 최종 화면이 제대로 보이는지 판단하려면 실제 결과를 열어 봐야 해요. 대화에 ‘완료’라고 적힌 것만으로 화면과 동작까지 확인했다고 볼 수는 없습니다.

3. 짧은 응답은 밖에서, 결과 판단은 맞는 화면에서 👀

{{section3}}

원격 제어는 Enterprise 조직을 제외하면 기본 활성화됩니다. Enterprise에서는 관리자가 조직 설정의 Security & identity에서 Remote control을 켜야 해요. 회사에서 쓴다면 개인이 연결할 수 있는 상태와 조직이 허용한 상태를 구분해야 합니다.

이번 변경 기록이 설명하는 휴대폰은 iOS입니다. Android도 같은 방식으로 제공된다고 넓혀 해석하지 않겠습니다. 지원 기기와 실제 연결 가능 여부는 자신이 사용하는 환경에서 판단할 부분이에요.

자리에서 잠깐 벗어난 동안에는 진행 내용을 읽고, 한두 가지 조건을 알려 주는 용도로 검토할 만합니다. 한편 복잡한 화면이나 여러 파일의 변경 내용을 꼼꼼하게 살펴보려면 작업 결과를 충분히 볼 수 있는 화면으로 돌아오는 편이 편하겠죠.

이는 기능의 제한을 새로 주장하는 것이 아니라, 읽을 내용에 맞춰 확인 방법을 고르자는 실용적인 판단입니다. 긴 수정 내용을 작은 화면에서 끝까지 읽지 않았다면 검토가 끝났다고 기록할 이유도 없어요.

원격으로 응답한 단계와 최종 확인한 단계를 나눠 기억하세요. ‘질문에 답했음 / 수정 진행 중 / 실제 결과 확인함’을 구분하면 다음에 PC로 돌아왔을 때 어느 부분부터 이어갈지 알기 쉽습니다.

휴대폰에서 다른 작업의 메시지를 읽다가 질문을 잘못 연결할 수도 있으니, 응답 전 현재 프로젝트와 요청 내용을 살펴볼 수 있어요. 짧은 답을 쓰더라도 어떤 대상에 대한 답인지 드러내면 맥락을 이어가기 좋습니다.

PC가 켜져 있는 동안 대화를 놓치고 싶지 않은 사람에게는 검토할 만한 변화입니다. 반면 노트북을 닫고 이동하면서도 같은 컴퓨터의 작업이 계속되길 기대한다면 공식 전원·덮개 조건과 맞지 않아요. 필요한 실행 환경을 먼저 고르는 것이 순서입니다.

오늘 해볼 행동은 ‘밖에서 답하고 싶은 질문’ 하나를 정해 보는 것입니다. 연결 후에는 그 질문에만 응답하고, 돌아와 실제 결과를 비교하는 작은 흐름부터 시작할 수 있어요.

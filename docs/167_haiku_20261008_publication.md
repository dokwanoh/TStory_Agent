## 다음 시도에 적용할 성공 경로

1. 현재 새 글 목표와 과거 글의 종료·저장 이력을 분리한다. 실제 관리자 로그인·최신 글·제목 중복0개를 확인한다.
2. 같은 게시봇 프로필에서 작성기를1개 연다. 각 문단이 독립된p가 되도록 네이티브 HTML 클립보드 붙여넣기를 이용한다. 일반 텍스트의 빈 줄 붙여넣기는 한p와br로 합쳐질 수 있다. 이번에는 이미지 업로드 전에 독립 문단으로 바로잡았다.
3. 네이티브 문단모양으로 번호 제목4개만 제목1로 지정하고 IT·태그를 입력한다.
4. 이미지 마커를 먼저 지운다. filechooser 대기를 먼저 등록하되 실패를catch하여 작업 세션 초기화를 방지한다. 최신 AX의 실제 attach-image 사진 항목을 네이티브 클릭하고 절대 파일 경로를 선택한다. 이번에 DOM 사진 클릭은 chooser를 열지 않았지만 네이티브 클릭으로 즉시 성공했다.
5. 업로드 직후 한 번의 AX에 이미지가 아직 없을 수 있다. 업로드 완료 UI를 읽은 뒤 해당 IMAGE를 선택한다. 이것을 재업로드나 작성기 교체로 대응하지 않는다.
6. ALT를 입력하고 실제 kimage-alt-submit 확인 버튼을 누른다. 확인이라는 접근성 이름이 실제DOM dialog 역할과 일치하지 않을 수 있어 최신 AX 인덱스로 확정한다. 인덱스 추출은 줄 시작의 숫자로 제한하여 ‘The focused UI element…’ 설명줄을 입력 필드로 오인하지 않는다.
7. ALT 저장 후 실제 해당 이미지의 최신 인덱스를 다시 선택한다. 본문 링크가 아닌 IMAGE 링크 도구·kimage-link-submit으로 제휴 URL을 확정한다. 표지 대표 배지의 체크를 확인한다.
8. 후반 HTML 모드에서 네이티브 전체 선택·복사로 현재 표시 소스를 읽고7개 이미지 코드를 메모리에만 보존한다. mode-confirm helper로 모드 확인창을 처리한다. HTML 배너3·요약표·버튼·글꼴만 보정하고7개 코드를바이트 그대로 돌려 넣는다.
9. 기본모드에서20개 본문 일치·제목 크기·고지·7링크·3배너·요약·인포그래픽 인접·GIF 위치를 한 번 점검한다. 공개/현재/IT 인터넷 선택→시도 기록→공개 발행 한 번→실제 관리자209개와 수정 링크221 확인 순으로 끝낸다.
10. 실제 공개 페이지에서짧은 작성자 상품 댓글을한 번 등록하고 고유 문장·comment ID로읽는다. DOM의 개행 정규화는 댓글 재등록으로 대응하지 않는다. 홈의 썸네일 이동과 원본 경로 일치를 읽고 공개 화면을 증거로 저장한다.

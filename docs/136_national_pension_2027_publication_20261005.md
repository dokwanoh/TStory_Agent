## 직접 첨부 복구 — 다음 작업에 재사용

1. CUA `rewriteDocumentation()`에서 확장 브라우저의 현재 지원 API를 확인하고 `agent.documentation.get("file-uploads")`를 읽었다. 단순 AX API만이 아니라 Chrome의 문서화된 `filechooser` 기능이 제공됐다.
2. 이전 파일 입력 자체 클릭은 chooser 대기 시간 초과였다. 실제 메뉴를 native AX `Expand`로 열고 새 상태에서 사진 항목을 찾았다.
3. `tab.playwright.waitForEvent("filechooser")`를 먼저 시작한 뒤 **그 사진 항목을 CUA AX 클릭**했다. 반환된 chooser에 정확한 절대 파일 경로를 `setFiles`로 지정하자 정상 업로드됐다. 본문 두 장과 GIF에도 같은 방법이 성공했다. 숨은 필드나 편집기 내부 데이터 주입은 하지 않았다.
4. 각 이미지의 native 대체 텍스트 입력을 저장하고 해당 마커만 삭제했다. 입력된 네 파일명과 순서는 편집기 DOM에서 확인됐다.
5. 편집 탭 연결이 사라졌을 때 10:22 자동저장 복구 안내를 확인하고 같은 초안을 복원했다. 제목·본문·분류·태그와 네 미디어·alt가 남아 있어 재업로드하지 않았다. 탭 소실 원인은 확정하지 않았다.

네이티브 앱 연결은 잠금 진단을 반환했지만 Chrome 연결·로그인·파일 업로드는 동작했다. 실제 Mac 잠금을 추정하지 않으며, 이번 완료에 사용자의 수동 파일 선택은 필요하지 않았다. 과거 잠정 중단 보고는 실제로 성공한 후속 결과로 명확히 정정한다.

## 저장과 공개 증거

- 관리 화면에서 `2027 국민연금` 제목 검색 결과 0건을 확인해 중복을 방지했다.
- 하나의 최종 공개 저장 후 관리 화면에 정확한 제목, 경제 분류와 10:27 시각이 나타났다. 공개 페이지의 수정 링크가 `/manage/post/192`를 가리켰다.
- 로그인된 공개 페이지에서 네 자산의 순서·alt를 확인했다. 일반 스크롤 후 각각 `complete=true`, `naturalWidth>0`이었다. 정지 이미지 세 장은 폭 1200, GIF는 폭 1000이었다. 공개 `og:image`의 자산 경로가 첫 썸네일과 일치했다.
- 익명 HTTP 조회는 `/192`에 200을 반환했고 정확한 제목, 네 article alt와 임시 마커 0개를 확인했다. 별도의 원격 픽셀·라이트박스·인쇄·광고 감사는 하지 않았다.
- 공개 결과 화면은 무시된 `public-post192.jpg`, 한 번의 저장 저널은 `publication-attempt.json`에 보존한다. 미디어·스크린샷·서명된 이미지 URL은 Git에 넣지 않는다.

후속 목표 확인에서 현재 익명 공개 HTML을 한 번 읽어 본문 **3,002자**, 표 1개, 전체 노란 요약 래퍼 1개, 정확한 네 미디어 파일명과 네 링크를 확인했다. 공단 요율표·가입내역 조회 버튼과 관련 청년미래적금 글 연결이 유지돼 있다. 최근 24시간 여부는 이 목표의 주제 선정 조건이 아니며, 국민연금의 적용 예정 요율과 월급 부담이라는 폭넓은 생활 질문을 선택했다. 관심·체류시간의 실측 수치가 있다는 뜻은 아니다.

실제 썸네일 파일의 큰 글자는 `2027년 10%`(66px), `내 월급 부담은?`(42px)이고, 별도 생성된 파란 3D 숫자·고지서·동전 장면에 오버레이됐다. 직전 post191의 짙은 종이 콜라주와 재질·팔레트가 다르다. 본문 사진 두 장도 직전 아파트 통화·상담 창구 대신 소규모 사업장 급여대장과 가을 주택가 배달 종사자 장면으로 바뀌었다.

실제 GIF는 **88개 서로 다른 저장 프레임, 총 9초, 무한 반복, 1000×562**다. 생성 스크립트의 90 프레임 중 동일 프레임이 인코딩 때 합쳐졌다. 한 계산 화면을 유지하며 `가입 유형 → 기준소득월액 → 해당 연도 요율 → 비교 확인`을 단계 표시, 탭 강조, 슬라이더, 요율·보험료 카운터, 증가분 강조로 설명한다. 장면을 넘기는 슬라이드 형식은 아니다. 차기 글도 해당 주제의 실제 입력·확인·결과를 먼저 정하고, 그 절차 안의 요소를 움직여야 한다.

다음 시도에서는 현재 지원 업로드 API를 먼저 읽고 준비된 정확한 미디어를 직접 첨부한다. 주제·사실 검증 뒤 글과 미디어를 제작하고, 큰 제목 오버레이·이전 장면과의 차이·연속 절차 모션을 준비 단계에서 확인해 저장 직전 반복 점검을 줄인다. 이번 후속 확인으로 게시글을 다시 저장하거나 새 글을 추가하지 않았다.

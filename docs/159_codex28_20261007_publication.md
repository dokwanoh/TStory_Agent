## 성공 경로 — 다음 작성기에 재사용할 실행 순서

1. 현재 소유자 지시와 동일 제목 기존 게시 여부를 확인한다. 완료된 이전 작성기의 종료 지시를 새 글에 재적용하지 않는다.
2. 출처와 상품 종류·옵션부터 확인하고 원고를 확정한다. 이번 상품은 로지텍 MX KEYS S, 그래파이트,920-011598,제조사축. API 키는 키체인 내부 사용만 했다.
3. 게시봇 프로필 한 개와 작성기 한 개에서 기본모드에 검토된 문단/제목 구조를 네이티브 HTML paste로 입력한다. 이미지마다 독립된 표식을 둔다.
4. 매 이미지 삽입 전 현재 전체 AX에서 본문 번호를 새로 얻고 해당 표식만 선택·삭제한다. 사진 메뉴 클릭 전에 filechooser 이벤트를 대기한 뒤 setFiles로 해당 로컬 파일만 지정한다.
5. 업로드 후 실제 네이티브 이미지 도구의 ALT·링크 입력창을 사용한다. 팝업에서 입력칸/확인 버튼 번호를 관찰한 뒤 붙여넣고 확인한다. AX diff에 기존 확인 버튼이 재출력되지 않아도 버튼 부재로 해석하지 않는다. 현재 선택 이미지·현재 번호를 사용한 V3 경로는 section3,4,5,GIF에서 연속 성공했다.
6. 표지의 실제 화면 위치에서 대표 배지를 선택한다. 선택 텍스트가 화면 밖이면 방향키로 커서 이동 후 현재 화면을 다시 관찰한다.
7. 네이티브 작업이 끝난 뒤 같은 작성기의 HTML 메뉴 전환을 시작한다. 클릭 응답을 먼저 기다리지 않고 실제 JavaScript confirm을 즉시 처리하는 mode-confirm helper를 사용한다. 이번 양방향 전환 모두 성공했다.
8. 네이티브 HTML 입력란에서 실제 키보드 전체선택·복사를 실행한 뒤 그 클립보드만 읽는다. 서명된 이미지 코드는 메모리에만 보존하고 전부 유지한 채 표식/서식/배너만 변경한다.
9. 본문16px/400, 제목23px/700, 투명한 첫 고지문, 요약표, 대표 표지, 태그/분류, 콘텐츠 링크7개/배너3개를 한 번 최종 확인한다. 공개·현재·IT 인터넷 설정으로 한 번 저장한다.
10. 저장 중 화면은 완료 증거가 아니다. 같은 관리자 목록에서 새 제목을 찾고 공개 페이지의 실제 ID를 확인한다. 결과가 불확실하면 기존 결과부터 읽고 저장을 반복하지 않는다.
11. 작성자 상품 댓글 한 개를 등록하고 실제 댓글 ID/작성자를 확인한다. 홈 썸네일의 글 이동을 유지하고 성공 범위와 공개 증거를 기록한다.

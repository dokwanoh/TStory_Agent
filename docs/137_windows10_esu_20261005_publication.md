## 주제와 실제 근거

일반 독자의 기존 PC 사용·보안·교체 비용 판단에 도움이 되는 ‘버전 → ESU 등록 상태 → 백업·전환 점검’을 선택했다. 관리 화면의 `윈도우 10` 제목 검색은 로딩 종료 후 0건이었다. 관심도·체류시간의 실측 수치가 있다는 뜻은 아니다. 최근 24시간 기준은 최신 목표에서 제거됐고, 작성과 미디어 생성 전에 현행 공식 본문을 읽었다.

핵심 근거는 [Microsoft 한국어 소비자 ESU 안내](https://www.microsoft.com/ko-kr/windows/extended-security-updates), [PC 상태 검사 안내](https://support.microsoft.com/en-us/windows/experience/compatibility/how-to-use-the-pc-health-check-app), [Windows 11 업그레이드 FAQ](https://support.microsoft.com/en-us/windows/deployment/install-upgrade/upgrade-to-windows-11-faq), [KB5126256 준비 패키지 안내](https://support.microsoft.com/en-us/servicing/os/windows-10/2026/09/kb5126256-windows-10-21h2-22h2-standalone-cbs)다. 현재 한국어 페이지의 소비자 ESU 종료일 **2027-10-12**와 기존 등록 자동 유지 안내를 사용했다. 오래된 다른 안내의 2026년 날짜를 새 글에 재사용하지 않았다.

일반 지원 종료와 ESU를 구분하고, 개인용 적격 22H2·계정·최신 업데이트 조건, 보안 업데이트 범위와 전체 지원의 차이, 준비 패키지 설치와 등록 완료의 차이를 설명했다. 가격·옵션은 실제 등록 화면과 지역 조건을 우선하도록 했다. PC 상태 검사 통과와 즉시 업그레이드 제공을 구분하고 백업을 권했다. 동일 출처 URL은 한 번씩만 연결했다. 공식 버튼 두 개와 관련 [post143](https://nedamma.tistory.com/143) 연결을 넣었다.

호스트 원문 수집에서는 첫 Microsoft 마케팅 페이지가 읽기 시간 초과였다. 해당 페이지의 실제 web 원문 읽기 결과를 그대로 보존했고, 나머지 공식 원문·관련 글은 HTML/text로 수집했다. 검색 스니펫을 원문으로 간주하거나 성공한 원문을 다시 요청하지 않았다. 수집 파일과 해시는 무시된 작업 디렉터리에 있다.

## 직접 게시와 최소 검증
